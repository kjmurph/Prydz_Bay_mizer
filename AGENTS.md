# Prydz Bay mizer model

@agentic_llm_instructions.md

A size-spectrum model of the Prydz Bay (East Antarctic) ecosystem, built on
**mizer** with **therMizer** temperature-dependent rates, forced with ISIMIP3a
climate and fishing inputs, and run as a Monte Carlo **ensemble** to propagate
parameter uncertainty. The scientific questions concern whaling-era depletion and
recovery, krill–predator competition, and how the size spectrum responds to both.

## The 19 functional groups

In `w_inf` order, as they appear in `species_params`:

mesozooplankton, other krill, other macrozooplankton, antarctic krill, salps,
mesopelagic fishes, bathypelagic fishes, shelf and coastal fishes, flying birds,
small divers, squids, toothfishes, leopard seals, medium divers, large divers,
minke whales, orca, sperm whales, baleen whales.

Nine of these have observed catch. `w_inf` spans 0.00316 g (mesozooplankton) to
1.03e8 g (baleen whales).

## How the work is organised

Work proceeds in numbered **phases**. Each phase gets one script in
`R/wmin_test/` whose header block states the protocol, what changed from the
previous phase, and why. **Read that header before touching anything** — it is
the real documentation, and it is usually accurate and current.

The member protocol (phase 61) is: apply the catchability draw, ramp the
abundance scaling in log space with `steady()` at each step, `steady()` *before*
capping the reproduction level at 0.9, then the tolerance ladder, then a 118-year
unfished spin-up and a stability screen (CV over the last 40 years, threshold
0.25). The gamma draw was deliberately dropped at phase 61; members now span
abundance and catchability uncertainty only.

## Traps

These are settled findings. Re-deriving them costs hours.

- **`species_params(params) <- ...` silently deletes `ext_encounter`.** The
  phase-57 out-of-domain subsidy lives there. Check it survived any parameter edit.
- **`getTrophicLevel()` is broken under therMizer** — it returns absurd values
  (orca ≈ 192). `getDiet()` *proportions* are exact; its absolute rates are not.
- **Filter to stable members before taking any mean.** A single divergent member
  once owned 83% of an across-member sum and moved a biomass SNR from 2.41 to 0.055.
  Medians are far more robust than means here.
- **The ensemble cannot be regenerated.** Members are basin selections: re-running
  the protocol reorders the ranking, and several top members are bistable. Rebuild
  from the *stored* ranking. Never "refresh" a stored member by re-running `steady()`
  — re-steadying halves the unexploited baleen whale stock and worsens the yield fit
  in 89% of members.
- **Re-projecting a stored member is safe and bit-exact** where the spin-up is
  unfished. That is why catchability can be refit without `steady()`.
- **`steady()` signals non-convergence with `message()`, not `warning()`.** Any
  guard built on `tryCatch(warning = ...)` is dead. The working guard is in the
  phase-44-and-later scripts.
- **`matchGrowth()` targets a placeholder.** With no `age_mat` column it falls back
  to `age_mat_vB()` from `k_vb`, which is a round default (0.2 or 0.5) for 14 of the
  19 groups. Target the base model's own realised `age_mat()` instead.
- **The whale response is reproduction-clamped.** Reproduction level ≈ 0.9976 pins
  numbers at `R_max`, so large krill losses barely move whale biomass. That is a
  real result, not a bug — but do not attribute whale insensitivity to anything else
  before checking the clamp.
- **Whale catch is stock-limited**: observed baleen catch is ~23.8x the calibrated
  stock, so no catchability value fixes it. Hold whale `q` at drawn values.
- **Never commit all 16 cores.** Leave one free; saturating them risks a hard
  shutdown that kills the in-flight run too.

## The live R session

`.Rprofile` calls `btw::btw_mcp_session()` when R starts **interactively in the
project root**, which hands the session to the `r-mizer` MCP server so agents can
read your objects and run code in them.

- Check it with `list_r_sessions`. If an agent cannot see objects you can see, it
  fell back to a scratch R process — that is the first thing to test.
- **Never call `btw::btw_mcp_session()` a second time.** It does not refresh the
  connection, it breaks it: the session stops answering and disappears from
  `list_r_sessions`, while the abandoned connection still counts as live and spoils
  session selection for every agent on the machine. Only restarting R clears it.
  Use `mizerAgents::connect_mizer_agent()`, which refuses to double-connect.
- Starting R from a shell does not read the project `.Rprofile` unless you start
  in the project root — relevant on the VM. Call `connect_mizer_agent()` there.
- Long projections block the console. Keep `t_max` modest unless asked otherwise.
